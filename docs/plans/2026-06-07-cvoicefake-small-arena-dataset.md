## Protocol → schema mapping (directory-as-label, like SONAR)
- **label** ← the label directory: `Bonafide/` → **bonafide**; every `*_generated/` → **spoof**.
- **`utterance_id`** ← derived from the **full relative path** (lang / label-dir / filename stem),
  e.g. `CVF_de_world_generated_common_voice_de_38024994_Gen`. The bare filename stem is *not*
  globally unique (the same CommonVoice clip is regenerated by each vocoder, all suffixed `_Gen`),
  so the id must include language + system. `path` = relative path (already globally unique).
- **extra `notes` fields:** `language` (de/en/fr/it/zh-CN), `system_id` (folder name, or
  `bonafide`), `source` = `CommonVoice`.

## Build approach
- **Source SR / format:** **16 kHz mono MP3** (MPEG Layer III) — confirmed via `soundfile`
  (libsndfile 1.2.2 decodes them; SR already 16 k, so **no resampling**). Clip durations ~3–5 s
  (sample: 4.1–4.2 s); whole-set min-duration handled in the builder (drop any < 1.0 s).
- **Path:** **re-encode → 16 kHz mono FLAC** (recommended). The files decode cleanly, so the
  skill's literal rule would allow a CLEAN raw-byte embed — but that would store **MP3** bytes,
  whereas every other Arena dataset stores canonical FLAC and not all downstream model decoders
  are guaranteed to handle MP3. Re-encoding here is a cheap **lossless-from-MP3 container change**
  (decode MP3 → FLAC, no resample). I'll still run the whole-set decode probe and fold it into the
  re-encode stage (per the re-encode+probe-folding lesson).
  - **Alternative if you want max speed / smallest repo:** CLEAN raw-byte MP3 embed (CommonVoice
    itself ships MP3 on HF, so it's defensible). Say the word and I'll take that path instead.
- **Shard sizing:** ~350 MB/shard; 16 k mono FLAC of 138 k clips ≈ ~12–18 GB → ~**35–55 shards**
  (finalized at build). Reference dir to fork: **`benchmarks/SONAR/`** (directory-as-label + MP3
  handling + `RIGHTS.md` precedent).
